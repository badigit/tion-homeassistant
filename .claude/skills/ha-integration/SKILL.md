# Интеграция Home Assistant — от нуля до каталога HACS

Собрано на живой работе (`tion_magicair`, август 2026): переписывание с нуля,
бронза 20/20, серебро 10/10, публикация и заявка в каталог. Здесь то, что
стоило времени и повторится в следующий раз.

**Первым делом** — `infra-knowledge` recall про **HA-Dev**: там адрес dev-инстанса,
доступ и цикл выкладки. Без него полсессии уходит на поиски.

## 1. Где проверять

**На Windows тесты не запускаются вообще.** Home Assistant импортирует `fcntl`,
это POSIX-модуль. `uv sync` пройдёт, `pytest` упадёт на импорте. Не трать время
на попытки.

Гонять на dev-инстансе, контейнером **того же образа ядра**, на котором
интеграция будет работать:

```bash
tar czf - custom_components tests pyproject.toml | ssh ha-dev \
  'rm -rf /mnt/data/tion-tests && mkdir -p /mnt/data/tion-tests && tar xzf - -C /mnt/data/tion-tests'

ssh ha-dev 'docker run --rm -v /mnt/data/tion-tests:/src -w /src \
  --entrypoint sh ghcr.io/home-assistant/qemux86-64-homeassistant:<версия> \
  -c "pip install -q --break-system-packages pytest-homeassistant==<версия ядра> pytest-timeout pytest-cov; \
      python -m pytest -q --cov=custom_components/<домен> --cov-report=term-missing"'
```

Выкладка на HA только `tar` по ssh: **в HAOS нет `sftp-server`**, `scp` падает
с `/usr/libexec/sftp-server: not found`.

## 2. Пин тестовой библиотеки

Прежний `pytest-homeassistant-custom-component` upstream закрыл и объявил сломанным.
Преемник — `pytest-homeassistant` из core: его версия всегда равна версии ядра.
Брать релиз с номером, равным версии ядра на проде (ядро 2026.11.2 — пакет
2026.11.2), иначе тесты зелёные на чужом API.

Пакету нужны три опции pytest в pyproject: `asyncio_default_fixture_loop_scope = "function"`, `addopts = "-p no:respx"` и `pythonpath = ["."]`. Фикстура `hass` уже разрешает кастомные интеграции.

Потолок на тест обязателен (`pytest-timeout`, `timeout_method = "thread"` —
на Windows иначе молча деградирует), см. общее правило `17-test-timeouts.md`.

## 3. Правило, без которого тесты бесполезны

**Новый тест обязан упасть на коде до правки.** Проверяется, а не
предполагается:

```bash
git archive <sha-до-правки> custom_components | tar -x -C /tmp/old
cp -r tests pyproject.toml /tmp/old/
# прогнать /tmp/old тем же контейнером — ожидаем красное
```

За одну сессию так поймано два теста-пустышки, и оба нашли **ревьюеры, а не я**:

- тест «логинится один раз» проверял только итоговый токен и был зелёным ровно
  при двух логинах;
- тест «чужое устройство не создаёт сущностей» проверял только `sensor.*`, а
  платформа `binary_sensor` в нём **падала целиком** — и тест это скрывал.

Отдельная ловушка: заглушка сессии, которая нигде не уступает управление,
**не воспроизводит гонку** — корутины идут по очереди, и тест проходит на
сломанном коде. Нужен `await asyncio.sleep(...)` внутри заглушки.

## 4. Шкала качества

Актуальные списки правил — только с сайта, не по памяти:
`developers.home-assistant.io/docs/core/integration-quality-scale/checklist/`.

Бронза (20 правил) закрывается быстро, если сразу писать на актуальных
паттернах: `config_flow` с `ConfigFlowResult`, `runtime_data`, `coordinator.py`
и `entity.py` отдельными модулями, `_attr_has_entity_name`, `unique_id` у всех
сущностей, `_get_reauth_entry()` для повторного входа.

Серебро добавляет: `PARALLEL_UPDATES` в каждой платформе (`0` для чтения,
`1` для команд), `ConfigEntryAuthFailed` и `HomeAssistantError` из команд,
`available`, покрытие **выше 95% по каждому модулю**, описание параметров
установки и настройки в README.

Формально уровень присваивают интеграциям **ядра**, кастомной его не дают —
корректная формулировка «соответствует правилам», а не «имеет бронзу».

## 5. Архитектура, до которой пришлось додумываться

- **Клиент протокола — отдельным модулем без импортов HA.** Сессию инжектить
  снаружи. Это и требование ядра дословно («we do not include any protocol
  specific code»), и практическая выгода: клиент гоняется обычным скриптом.
- **Ошибки облака разделять на три класса:** auth (ведёт в reauth),
  connection (ведёт в повтор), command (ошибка пользователю). Смешение стоит
  дорого: `403` от captive portal, принятый за отозванный токен, роняет запись
  в reauth, **и она сама не поднимется** после возвращения сети. Отличать по
  телу ответа: облако говорит JSON, портал отдаёт HTML.
- **У команды нужен общий дедлайн.** Двадцать попыток по пятнадцать секунд
  складываются в шесть минут удержания блокировки.
- **Неполный снимок телеметрии — не повод выдумывать значения.** Если протокол
  принимает состояние целиком, подстановка нуля выключит прибор. Отказ заметен
  и обратим, «успешная» разрушительная команда — нет.
- **Состав сущностей должен следовать за снимком**, а не за первым опросом:
  прибор, бывший offline при старте, иначе останется без сенсоров до
  перезагрузки. Слушатель координатора + запоминание по `unique_id`.
- **Устройства:** хаб + `via_device`, комната через `suggested_area`. MAC
  локации **не отдавать хабу**, если он совпадает с MAC устройства — HA
  отвергнет второе устройство с тем же адресом и выбросит все его сущности.
- Списки режимов и границы — **свойства**, а не поля из `__init__`: иначе
  неполный первый ответ замораживает их до перезапуска.

## 6. Миграция со старой интеграции без потери истории

Сущности держатся связкой (домен, платформа, `unique_id`). Правка этих полей
в `.storage/core.entity_registry` при **остановленном** ядре сохраняет
`entity_id`, имена, иконки, комнату, историю recorder и статистику — и не
требует править ни `configuration.yaml`, ни карточки дашборда.

Перед правкой `.storage` — резервная копия. Порядок: стоп ядра → правка →
`ha core check` → старт.

## 7. Публикация в HACS

Проверить фактами, а не по памяти: **приватные репозитории HACS не
поддерживает вообще** («can only get publicly available information»).

Перед открытием репозитория — аудит **всей истории**, не только дерева:

```bash
git log --all -p | grep -iE "^\+" | grep -oiE \
  "(ghp_[A-Za-z0-9]{20,}|github_pat_[A-Za-z0-9_]{20,}|xox[bap]-[A-Za-z0-9-]{10,}|AKIA[A-Z0-9]{16}|-----BEGIN [A-Z ]*PRIVATE KEY|eyJ[A-Za-z0-9_-]{30,}\.)"
git log --all --format='%s%n%b' | grep -iE "<внутренние хосты и адреса>"
```

Помнить: **force-push не удаляет старые объекты с GitHub** — они остаются
доступны по прямому SHA до их сборки мусора. Если в истории оказался
настоящий секрет, переписывания мало: нужен отзыв секрета и пересоздание
репозитория.

Минимум для HACS: `hacs.json` с `name`, `custom_components/<домен>/` с
`domain`, `documentation`, `issue_tracker`, `codeowners`, `name`, `version`
в манифесте, значок `brand/icon.png` (с HA 2026.3 он лежит **внутри
интеграции**, PR в `home-assistant/brands` не нужен, папка
`custom_integrations` там объявлена устаревшей).

Ключ `homeassistant` в `hacs.json` — **проверенный** минимум, а не на глаз.
Определять по фактическому наличию использованных констант в тегах ядра:

```bash
for v in 2026.6.0 2026.7.0; do
  gh api "repos/home-assistant/core/contents/homeassistant/const.py?ref=$v" \
    --jq .content | base64 -d | grep -c "class UnitOfRatio"
done
```

## 8. Заявка в каталог HACS

PR в `hacs/default`, файл по типу (`integration`), ветка **не** от `master`.

- Заполнить шаблон целиком и **сохранить скрытый маркер** `<!-- tid:... -->`:
  по нему видно, что шаблон использован. Ревью не запрашивать — за это
  закрывают прямым текстом.
- Чеклист требует релиз, созданный **после** успешного прогона проверок.
  Если релиз старше, чем задание `hacs/action` в CI, — выпустить новый.
- В CI обязаны быть **оба** задания: `hassfest` и `hacs/action@main`
  (`category: integration`).
- Строку в файл вставлять **текстом**, а не пересериализацией JSON: в
  апстриме есть строки с висячими пробелами, и `json.dumps` «починит» их,
  превратив diff `+1` в `+7 −6`. После вставки проверить, что файл остался
  валидным JSON и отсортированным по нижнему регистру.
- Агрегирующая проверка «Action checks completed» может упасть раньше, чем
  завершится `HACS action`. Это гонка: дождаться, а не чинить.

## Чего этот скилл не покрывает

Путь в **ядро** Home Assistant. Там три PR в три чужих репозитория, требование
вынести протокол отдельным пакетом на PyPI, минимум бронза и подпись code
owner под многолетним сопровождением. Отдельный проект на недели.
